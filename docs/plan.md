# Plan: OMP Pricing (simple version)

Goal: take a located Excel parts list, get prices and details from DigiKey (and later other distributors), and produce the filled Excel. Receiving files and sending results by email are separate later topics.

Do one step at a time. Stop after each step and wait for the owner. Rules and business logic are in `AGENTS.md`. Each step ends with a report in the format given there.

## Step 1: Project and Excel in/out

- Create the solution `OmpPricing.slnx` with `src/OmpPricing.App` (console) and `tests/OmpPricing.Tests`, `.gitignore` (VS, plus output/, state/, logs/), README with run steps, Serilog console and file logging, user-secrets set up.
- Create the `rules/` folder and its five files with the seed content described in `docs/test-data.md` (countries.txt generated by code from Sheet1 of the sample file). Make the app copy the folder to the output folder at build time, and load it from the repo's `rules/` path.
- Read `tests/samples/LT2026100009.xlsx` by column position (A4) and apply the input rules in A6 rule 1 and A9: row-number identity, generic parametric rows, `x` wildcards (detected before uppercasing), multi-MPN cells, trimming.
- Write results into the sender's own workbook (open and edit, never rebuild). Keep Sheet1, its table and the validations on columns S, T and U. After saving, reload and assert the validations still exist. Write Yes/No exactly and COO only from `rules/countries.txt`. Add the `Offers` sheet and highlight rows that are not Priced.
- Define `IInputSource` with `FileInputSource`, and `IResultSink` with `FolderResultSink`, and a `PricingPipeline.RunAsync(IInputSource, IResultSink)` that for now fills fake prices. `--file <path>` builds the pipeline from those two classes.
- Acceptance: 145 data rows read, columns 1 to 6 unchanged in the output, Sheet1 and the three validations preserved, about 67 generic rows marked NeedsReview with no provider call, the `BLM15GG221SZ1x` row detected as a wildcard, the five-MPN cell yields one primary MPN plus alternates, tests pass.

## Step 2: Provider framework and DigiKey

- Build the provider framework from AGENTS.md "Providers": `IPriceProvider`, `PartQuery`, `ProviderResult`, the normalized `Offer`, `ProviderRegistry` (reads `Providers:*` config) and the shared `Throttle`. Add the shared contract tests that every provider must pass.
- Build `Providers/DigiKey/` as the first provider (five files): token request and renewal, product details by MPN, the Duplicate Products retry with manufacturerId, comma encoding, required headers, rate-limit headers, mapping to `Offer`.
- Implement the part matcher in `Pricing/` (A6 rule 2 and the wildcard rule in A9) using `rules/`. It works on `Offer`, not on DigiKey types.
- Throttle with the DigiKey limits from A5 (120 calls per minute, 1,000 per day); a 429 becomes `Throttled`.
- Add a `FakeProvider` (test only) so the pipeline can be tested without DigiKey.
- Tests use fixtures built from `docs/test-data.md` and a stub `HttpMessageHandler`. No live calls.
- Acceptance: contract tests pass for DigiKey and FakeProvider; fixture tests for exact match, packaging variant, wildcard, duplicate manufacturer retry, 429; a generic row makes zero provider calls; nothing outside `Providers/DigiKey/` references a DigiKey type (add a test or a simple namespace check for this).

## Step 3: Pricing and the 22 columns

- Implement offer selection and the compulsory columns 7 to 21 (A6 rules 3 to 9) using `rules/supplier-terms.json`, `rules/coo-rules.json` and the packaging, RoHS and authorised-distributor mappings.
- Line statuses and Remarks as in A6. The output is always written.
- Wire everything into `--file`: read, look up, select, write.
- Acceptance: the numbers in `docs/test-data.md` (Qty 1 to 200000, PACKAGING=CT, expected output row, Incomplete vs Priced with test rules) all pass. Running `--file tests/samples/LT2026100009.xlsx` with fixture-backed DigiKey keeps all 145 rows and the dropdowns, and no row is Priced with a missing compulsory cell.
- Owner milestone after this step: run it once with the real DigiKey keys on the sample file and review the output by hand.
